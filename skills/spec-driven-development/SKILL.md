# spec-driven-development

## Description
Write a PRD/spec before writing any code for new features or projects.

## Process
1. **Ask** — Clarify requirements with the user (what, why, boundaries)
2. **Draft spec** — Objectives, key commands, project structure, code style, testing approach
3. **Verify** — User approves spec before any code is written

## Anti-Rationalization
- "I know what to build" → Write it down. Spec catches gaps.
- "This is quick" → If it touches >1 file, it needs a spec.
- "We already discussed this" → Spec is the single source of truth.

## Verification
- User explicitly approves the spec
